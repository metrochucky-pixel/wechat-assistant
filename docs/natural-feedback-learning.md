# 自然语言纠正的候选学习

2026-10-04，接续长期记忆与发送边界修复。新增 natural_preferences.py；没有新增外部模型调用、定时通知或群消息。

支持的自然表达例子：

| 原话 | 可提取的偏好 |
|---|---|
| 以后回复不要这么长 / 以后别回这么长 | 简短 |
| 解释具体一点 / 回复详细一点 | 更具体 |
| 这句不像我，以后自然一点 / 别写得像客服一样 | 自然口语化 |
| 以后少用表情 / 表情太多了 | 少用表情 |
| 这句不像我 | 只记录候选，没有足够信息生成具体规则 |

这是保守的句式识别与证据判断，不是任意自然语言理解。未知表达不会被编造成偏好；匹配到纠正线索但无法完整理解时保留unspecified候选。转述、引号、假设、示例、操作权限或敏感操作类文本不转成风格规则。只有固定的长短、表情、自然措辞三个表达维度能输出预定义提示，原话本身不拼入模型规则。

先经过原有owner_likely来源识别（新连续事件、两次一致读取、排除bot写入/草稿等）。明确点名bot/机器人/分身的具体纠正可在该群生效；否则必须在首次观察时，紧邻一条已经确认发送、内容相符、五分钟内的本账号bot消息，且中间没有别人插话，才能视为对bot的直接反馈。无法绑定对象的内容只存候选；这里仍是保守推断，不能绝对证明同账号消息由机主手动发出。

候选记录含原话、来源事件、群、目标bot任务、提取结果、状态和原因，保存在权限受限的本地SQLite数据库。新候选默认只作用于当前群，不扩散到其他群。手机主进程与后台生成worker均通过ContextVar设置当前会话，退出/异常时还原，load_persona实时加载本群已激活偏好。人工明确偏好（包括停用）优先，本群纠正优先于弱统计倾向。旧的逐词禁用词机制保持原有兼容行为。

明确只针对“这次”的评价不转长期偏好；同条消息内矛盾要求保留候选；同群同一维度较新的有效纠正替代旧的，记录superseded状态。来源失效会撤销派生规则，加载时也检查来源，不能等后台下一轮才停止使用。候选及来源保留窗口为90天；它不是永久事实档案。

无需逐条确认，也不会主动发飞书。查看：`python3 tools/owner_memory_status.py`。管理已核对的候选：`--approve <id>` 或 `--reject <id>`；拒绝不会因下一次汇总而自动恢复。批准只能启用已有具体风格值，不能把“这句不像我”自动猜成短句或幽默，也不能将一次性修改变为永久规则。默认查看不输出原话；需要核对时可读取指定候选的本地source_text。

验证：新增23项测试，包含对话中讨论过的纠正表达及正反例、群友插话导致无法绑定、实际capture到候选的完整链路、群隔离、主/后台persona加载、来源撤销、拒绝持久化、人工优先级、一次性/未来表达混合以及矛盾与替代关系。完整升级门禁249项测试及35项历史结构回放。所有测试在临时数据库执行，未向真实群发送消息；测试结果不等同于对所有自然表达的理解准确率。
