# 第一轮：读屏复用、回复分流、耗时诊断

2026-10-04。在独立目录 /path/to/source 的 codex/bot-round1 分支开发，基线是修改前的运行程序；未推送公开仓库。

- 身份预检与消息提取共用 `_read_chat_frame`，返回标题、输入框、消息及最新位置；同一次会话访问按精确像素摘要复用，排除顶部时钟，包含标题、消息和输入框。缓存30秒过期，最多24项，访问结束释放；持久消息缓存增加版本与日期摘要。
- 已用实际滚动确认的底部位置，只对同一访问、同一画面短期复用；新消息、输入框变化、图片页返回等画面变化会失效。清楚的纯文字上下文规划直接使用结构化消息，含图片或不确定信息仍传图。
- 新建 chat 事项允许文字快速拟稿：需当前画面确认是聊天且已到最新位置、消息发送者及文字明确，无图片/知识查询/个人决策等信号。调用现有人设生成至多120字回复；模型可升级为完整流程或需本人确认。旧任务无 kind 时保持旧流程。快速拟稿不绕过事项权限、群身份、草稿所有权、发送提交或回执检查；带 job 的发送视觉校验每次新读。
- `performance_visits` 表保存每次访问的总耗时、阶段耗时、API实际调用数、缓存命中、分流、规划原因、跳过/失败原因。异常也记，最多2000条；不记录API密钥、提示词或截图。阶段含嵌套，不可把各阶段耗时直接相加。
- 查询：`python3 tools/performance_status.py --limit 20`，只读数据库，不操作手机或调用模型。`WECHATBOT_CACHE_VISUAL=0` 可禁用画面复用，发送保护始终开启。

部署核验：后台已输出 round1 v1 启用标记，运行源文件与分支版本逐字节一致，ADB处于device。首次真实会话记录已落库：37.59秒、6次API、缓存命中0，结果draft_blocked（保留未核实草稿），未发送。说明新诊断能明确指出当前阻塞，但不能据此宣称实际群聊整体提速；该会话走草稿核验路径，没有进入快速拟稿。另以明确的合成纯文字闲聊测试实际API：符合快速路由，拟稿2.89秒，未发送。


## 旧草稿重复阻塞修复

37.59秒访问包含6次API调用：清理前、聚焦后、清理后均完整读屏并进入成员页核验身份。聚焦后离开聊天页可能丢失输入焦点，旧草稿因此反复无法清空。现在只在聚焦前核验身份；使用同次访问已核实的画面证据，清理过程中留在聊天页，检查标题像素连续性、草稿所有权及清空结果。发送流程的身份核验不变。清理失败记录明确原因，间隔5分钟再试，不删除用户改写的草稿。清理成功后重新截图，避免使用旧画面。

现场验证：张三丰所在群原bot草稿已实际清空，截图 /tmp/draft-latency-after.png 确认输入框为空；清理标志及草稿所有权字段已移除。一次性修复探测33.03秒、5次API，未发送消息，不能算作端到端回复耗时改善。随后同群清理入口复测0.27毫秒、0次读屏、0次API，确认不再重复该清理流程。63项相关回归通过（技术恢复7、可靠性29、首轮性能14、会话集成13）；最后指标分类修正后重跑技术恢复及性能21项通过。

## 持续无进展保护

### 集中身份核验失败修复（后续版本）

现场发现多个会话的列表定位错行：模型估计坐标与真实头像行中心不一致；保留真实行坐标，由程序把每行裁剪并印制R标签，模型只读标签和会话名。解析器拒绝未知/重复标签，点击不再应用旧坐标偏置；仍核对最新头像指纹以防列表重排。列表标题和底部导航变化时停止这一轮点击。身份失败记录实际标题，避免只有泛化原因。文件传输助手不参与自动聊天调度。

已在手机现场验证粉丝群04、示例讨论群、示例机主 OWNER三处正确进入且核验通过。另一个未命名三人群因列表名字被截断，原规则只有一个完整成员名而拒绝；逐一打开三名成员资料核实完整名字，写入仅生产数据库的 verified_group_members。运行时仍要求人数、全部成员与绑定一致，并保留现有成员集合核验，不使用模糊会话名称放行。该群现场复测通过。无测试消息发送。

此版本替代原逐会话通知：收集60秒后合并待通知会话；全局30分钟内最多一次异常汇总，保留通知认领、超时不重复发送规则，并兼容上线前已发送记录。集中异常不再逐群推送。83项相关测试通过（导航4、故障保护15、可靠性30、性能14、草稿恢复7、会话集成13）。

新增 bot_progress.py，按会话持久记录技术失败。连续3次身份核验失败、草稿阻塞、观察不完整、发送失败/未确认或总预算超时后，暂停进入该会话5分钟；再次失败退避10、20、最多30分钟。其他群继续调度。暂停检查放在点开会话之前，直接调用处理函数也有同样保护；MentionOnly 的 @ 发现仍先保存，暂停不产生发送授权。恢复检查通过原流程重新核验身份、读最新消息，发送或明确无需回复后关闭异常；合并等待、冷却、等待机主和仅被@策略不算成功或失败。

故障记录写入 outbox 的 conversation_progress，重启保留；不改写任务状态、草稿或发送回执。发送不确定仍走原核对流程，不直接重发。原进程内发送熔断继续有效，其重复通知移除，统一由新保护负责。独立通知线程给既有机主飞书通道发一条状态提醒，不占用手机工作线程，不要求逐条确认。通知先持久认领再发送，避免重启/超时后重复通知；失败或结果不明记为 unconfirmed，不宣称已送达、不自动重发。正常恢复后关闭该异常；新的异常周期可再次提醒。
