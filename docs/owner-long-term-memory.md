# 本人表达与长期偏好

2026-10-04。新增 owner_memory.py，现有 persona.md、voice.md、about_me.md、people.md 和旧 memory.json 不变。保存位置为权限0600的本地 outbox.sqlite3 新表：owner_samples、owner_daily、owner_preferences。

微信右侧消息只能证明来自同一个账号，无法绝对证明是机主手动发送。新消息必须来自连续观察、self/certain均为true、没有引用/链接/媒体占位，经间隔至少10秒的两次一致读取，并排除当前群全部已记录bot回复、拥有的草稿、近似OCR文本以及sending/uncertain/prepared事务，才标记owner_likely。初始屏幕历史、其他群友、身份不明的内容不回填。后续发现bot来源会撤销样本及由其派生的自动偏好。其他外部自动化或未记录的发送仍可能被误归类，因此这些样本不能作为个人事实或操作授权证据。

后台线程每60秒进行轻量本地统计，无额外模型调用、无设备操作。按自然日累计表达数量、短句和表情情况；至少10条、跨3天、短句比例80%以上才产生“日常接话简短”的弱偏好。语料本身不注入全局提示，不从个人话题推断性格、身份、关系、经历或承诺。原始样本90天/最多2000条，统计随样本重建；自动倾向证据不足时停用，不承诺只增不减。

明确纠正支持保守白名单：本人来源样本整句为“bot/机器人/分身，以后回复短一点/详细一点/少用表情/不要表情”，或“bot 别再说某词”。引述、泛泛对群友的要求及自由形式指令不会成为规则。自动纠正有来源事件ID，纠正被识别为bot文本后撤销。自动纠正不覆盖人工明确设置。

机主在当前助手对话中明确确认的偏好可经管理工具永久保存：`python3 tools/owner_memory_status.py --set brevity --value '"short"' --evidence '机主明确要求简短'`；避免词为JSON字符串数组。仅支持brevity、emoji、avoid_words三个表达维度。`--disable brevity`停用并阻止自动重建该键；再次显式设置可恢复。无参数查看来源数量、各日统计数量、偏好来源及是否启用，不输出聊天样本。

load_persona每次生成实时加载已保存表达偏好，明确人工规则优先于自动观察；它们仅约束措辞，不扩大执行权限或发送范围。已接入现有后台worker和同步回复路径。本人发言仍不触发机器人自问自答。

既有“排长/排面”措辞纠正作为来自本次会话历史的明确偏好迁入避免口头禅列表；不把bot自己的旧回复当作机主语料。新样本从上线后积累，不伪造已学习的天数或效果。

验证：13项新增离线测试，覆盖两次读取、机器人回复/不确定发送排除、基线与群友排除、延迟撤销、跨天阈值、明确规则优先级、纠正白名单、关闭偏好不被自动重建，以及运行时load_persona实际加载。完整门禁212项测试和35项结构回放。
