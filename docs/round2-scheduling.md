# 第二轮：减少无变化轮询，优先处理需要回应的会话

2026-10-04，分支 codex/bot-round2，基线 454e87e。第一轮后的现场日志显示，粉丝群同一话题反复进入并判定无需回复，每次约9–12秒；这不是生成答案耗时，而是重复读屏。

- 列表识别结果最多复用20秒：精确截图摘要（不含状态栏时钟，包含日期）、巡逻模式、待答目标集合必须同时一致。新预览、未读标记、列表重排、目标集合变化、到期都会重新识别。返回值复制，避免排序等操作污染缓存；无效识别结果不缓存。该缓存仅用于发现会话，不用于身份验证或发送。
- 刚完成“无需回复”的会话，可在同一行全部像素无变化时暂缓进入，最多60秒。头像、未读角标、预览文字、时间及名称都参与摘要；跳过不延长到期时间。新@、保留的@发现、未读标记、待答事项、待观察目标均绕过暂缓。发送成功、发送不确定、观察失败、技术退避、等待机主不标记为无需检查。重启后重新检查。
- 调度顺序为新@、有待答任务、其他会话；同类继续按最久未尝试排序。保留原会话失败冷却、总轮询预算和发送前核验。
- 新增 scheduler_counts，分日期累计列表模型识别、列表缓存命中、无变化会话跳过次数，保留30天。查询：python3 tools/scheduler_status.py；无手机/API操作。

验证：13项新增调度测试，及可靠性30、导航4、首轮性能14、会话集成13、草稿恢复7、故障保护15项相关回归，共96项。真实保存列表截图只读回放：模型识别4.603秒，同图复用0.015秒，结果一致；使用临时数据库，没有操作手机或发送消息。该数字只衡量列表复用，不代表完整回复耗时。预览可能无法展示连续同文或同类媒体的差别，因此仍保留60秒强制复查，而不永久跳过。

上线核验：运行源文件逐字节比对通过，后台 round2 v1 标记已输出，单一手机工作进程且ADB为device。首轮粉丝群检查9.17秒后判定无需回复，后续两轮真实调度均跳过该未变化会话，其中一次复用列表识别；数据库记录 quiet_row_skipped=2、list_cache_hit=1。说明新调度实际生效，不是只做了离线测试；未据此声称生成或发送全流程达到特定延迟。
